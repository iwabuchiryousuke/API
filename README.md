# SBI家族売買記録 v3.5.15

SBIのPDF・資産・NISAを取得し、内容を確認してから台帳とExcelへ反映するWindowsアプリです。既存Excelのシート・セル位置・列幅・数式・書式は維持しています。出力する値が直接確認値か当日実測の参考値かは、既存の確認欄で区別します。

## 今回の変更

- 日本時間の**暦月末16:00・毎月1日16:00**に、A～Dの資産・NISA枠を取得する月次処理とWindowsタスク登録機能を追加しました。
- 各口座の資産取得を先に行い、その後、月初1日だけ電子ポストのPDF取得・保存を試みます。**自動処理では売買台帳への一括登録を確定しません。**
- 月末・月初の実取得時刻、取得できた項目、遅延・不足を月次画面と比較CSVで確認します。既存の売買記録Excelの配置・数式・書式は変更しません。

月次処理のWindows実機での起動、スリープ解除、実際のSBI画面での取得成功は未確認です。以下の設定条件と検証範囲を確認してください。

### v3.5.14までの主な改善

- 電子ポストへの移動で元のタブが置き換わった場合も、同じログイン状態で確認済みのSBI画面へ戻して資産を読む処理を追加しました。
- 預り金フィルター変更後に必要な「更新」と表示の反映を待つ処理、現金より遅れて表示されるNISA枠を待つ処理を見直しました。
- 「非課税口座内上場株式等払出通知書」を既知の未解析通知として識別し、原本と理由を残します。NISAからの払出し・口座区分移動は未反映で、売却・税額・取得単価を推定しません。
- 「取得した資産を確認」に、最新値・取得済み未反映、前月末・当月1日、取得日時の履歴を分けた表示を追加しました。表示だけでは台帳へ登録しません。

これらはローカルの模擬画面・生成文書・隔離データで検証する変更です。実際のSBI画面やWindows実機での成功は、まだ確認できていません。

## 月末・月初16時の自動取得を設定する

### 最初に1回行うこと

1. 最新版を、普段使っているアプリフォルダへ更新します。SBI・Gmail連携・口座名義の設定は、**そのPCの同じWindowsユーザー**で済ませてください。
2. Windowsのタイムゾーンを **「(UTC+09:00) 大阪、札幌、東京」** にします。異なる設定ではタスクを登録しません。アプリがWindowsの時刻やタイムゾーンを変更することはありません。
3. `show_monthly_tasks_plan.bat` で登録予定を確認できます。この操作はタスク登録・SBI接続を行いません。
4. **`setup_monthly_tasks.bat`** を実行し、月末と月初の2タスクを登録します。既定では同じWindowsユーザーにログオンした状態で動かす方式です。
5. **`test_monthly_tasks.bat`** で、今の時刻の資産取得を試します。テストは資産だけが対象で、PDF取得や売買台帳への反映は行いません。月末・月初16時の取得成功としても記録しません。
6. `monthly_tasks_status.bat` とアプリの月次画面で、登録・次回予定・実行結果を確認します。タスクの結果コード0だけでは、SBIの全項目を取得できた証拠にはなりません。

解除は `remove_monthly_tasks.bat` です。このアプリフォルダ・同じユーザー向けの2タスクを解除し、台帳・PDF・認証設定・取得履歴は削除しません。アプリフォルダを移動する場合は、旧フォルダ側で解除してから、新しい場所で登録し直してください。

追加認証・Gmailの再許可・受信先設定など、人による確認が必要だと判定した口座は「認証待ち」として保存し、**同じ予定枠での自動再試行ではログイン・PDF取得を繰り返しません。** アプリの口座・認証設定で原因を解消してから `test_monthly_tasks.bat` を実行してください。明示的なテストで成功した口座・名義の待ち記録だけを解除し、失敗したテストでは解除しません。通信障害・タイムアウト・利用上限などの一時的な失敗は、認証待ちと区別します。

### 何を、いつ記録するか

| 予定 | 先に行うこと | 資産取得の後に行うこと |
| --- | --- | --- |
| 暦月末の16:00（日本時間） | A～Dの資産・NISA枠を順に取得 | 月末の月次記録を保存 |
| 毎月1日の16:00（日本時間） | A～Dの資産・NISA枠を順に取得 | 月初の月次記録を保存し、電子ポストPDFの取得・保存を試行 |

土日・祝日でも暦日を使い、前営業日へずらしません。たとえば `2026-10-31 16:00` と `2026-11-01 16:00` が、11月の比較対象です。A～Dを順番に処理するため、**全口座を16:00ちょうどに同時取得するものではありません。** 取得は予定より遅れることもあり、実際の取得時刻・遅延・不足項目を残します。

16:00は取得を開始する予定時刻です。表示された価格や残高が、その時刻に確定した終値・最終残高であるとは断定しません。月次画面と比較CSVの差額も、入出金・売買・為替変動などを含む**表示額の増減であり、運用損益ではありません**。未取得項目を0とみなして合計しません。米ドル元額と円評価も分けます。

月初のPDFは取得・保存までです。あとでアプリから **「取得済みPDFを全口座へ一括反映（A～E）」** を実行し、内容を確認して登録してください。月次記録・比較CSVは既存の売買記録Excelとは別です。

同じ暦日の遅延起動は、その実時刻を記録します。翌日以降に起動しても、取り逃した前日の16時取得へ読み替えません。取得していない過去残高や利益を、現在値・保有株数・前月比から作ることもありません。

### PCを無人で動かす条件

既定の登録方式では、**同じWindowsユーザーにログオンしたまま**にしてください。画面ロック・画面消灯中も、画面を表示しない処理を実行する設計です。サインアウトすると既定方式では実行できません。実際のロック中動作もWindows実機では未確認です。

サインアウト中の実行を必要とする場合は、コマンドプロンプトで `setup_monthly_tasks.bat Password` を実行します。安全な入力画面で求めるのは、**同じWindowsユーザーのWindowsパスワードで、PINではありません**。アプリのファイル・起動引数・ログへパスワードは保存せず、タスク用の資格情報はWindowsが管理します。Windowsパスワードを変更したら再登録してください。Windows Hello・パスワードなしの設定や組織の権限設定によって、この方式を使えない場合があります。Gmail通信とDPAPI設定を利用するため、S4U方式への切替は行いません。

スリープからの復帰を要求する設定で登録しますが、実際に復帰できるかはWindows・機器・電源設定にも依存します。AC電源への接続と、設定項目がある場合は**スリープ解除タイマーの許可**を確認してください。ノートPCのふたを閉じたときの動作、休止状態、機器の省電力設定によっても起動できないことがあります。タスクに再試行を設定しても、追加認証や設定不足を自動的に解消するものではありません。

**PCの電源が切れている間は実行できません。** 毎月の時刻に確実に稼働できるWindows端末が必要です。常時稼働の別のWindows端末へ移す場合も、その端末でPython・Edge・各口座・Gmail連携を設定し直してください。DPAPIの暗号化設定はPC・Windowsユーザーに結び付いており、認証ファイルを単にコピーして無人実行できるとは限りません。

登録時は同梱コードから一時PowerShellスクリプトを生成し、そのプロセス限定の実行設定で動かします。Windows全体の実行ポリシーを変更しません。組織の強制ポリシーやユーザー権限で登録できない場合は、状態確認の結果を確認してください。

## 取得して一括反映する

1. 必要なら「対象月末まで」に `2026-10` などの対象月を入力します。
2. **「4口座のPDF・資産・NISAを取得して一括反映」**を押します。A～DのGmail認証・SBIログイン・名義確認後、PDF、現在資産・NISA、日付を指定した資産の取得を試みます。
3. 確認画面で追加件数・未解析書類・未取得項目を確認します。「登録前Excelを確認」で内容を開けます。
4. **「登録してExcel出力」**で確定します。A～Eの保存済みPDFと取得証跡をまとめて検査し、台帳へ反映してExcelを出力します。Eは保存した資料のみ対象で、自動ログインしません。

口座選択はPDFの取得・保存先を指定します。**PDFの台帳反映は、選択口座に限らずA～Eの一括処理です。** 「選択口座のPDFだけ取得」と「手元のPDFを保存（選択口座）」は保存のみです。その後、**「取得済みPDFを全口座へ一括反映（A～E）」**で確認・登録します。この反映操作はSBIへ接続しません。

一括処理が途中で止まっても、保存済みPDFと名義を確認済みの資産取得証跡は保持します。資産画面では未反映の証跡も確認できます。証跡の破損や名義不一致は警告し、登録済み値だけを表示します。確認の取消・取得失敗を台帳登録の完了とは扱いません。

## 資産画面と通貨

「取得した資産を確認」は、次の3つに分かれます。

| 表示 | 確認する内容 |
| --- | --- |
| 最新の取得値 | 登録済みか取得済み・未反映か、画面ごとの取得日時、円評価、米ドル元額、NISA枠。以前の取得値を含む場合も表示します。 |
| 前月末・当月1日 | 表示基準日を直接確認した値、手動確認値、当日実測の参考記録、未取得の区別。 |
| 取得日時の履歴 | 取得を実行した日本時間、取得画面、画面上の表示時計、取得できた項目。 |

株式の単独の読取値と、投資信託・債券等も含む集計値を区別します。合計を構成する項目に未取得があれば、その項目を0とみなして合計しません。単独額を読み取れていても、Excelの合計欄は確認できるまで空欄になる場合があります。読み取れた株式単独額は資産画面で確認できます。

外国株式・外貨現金の**円評価**と、米ドル現金の**元通貨額**も区別します。買付余力を現金に代用せず、ドル額を円欄に入れません。スクリーンショットに外国株式や米ドルの項目が見当たらないことは、保有額0の証拠にはなりません。確認できない項目は「未取得」です。

## 前月末・月初1日の値

対象月が `2026-10` なら、取得対象日は **`2026-09-30` と `2026-10-01`** です。空欄なら日本時間の今月を使います。

優先するのは、SBI画面の基準日を直接確認した値と既存の手動確認値です。直接確認できない場合は、対象日そのものに取得した実測記録を参考として利用します。月末日はその日に最後に取得した記録、月初1日はその日に最初に取得した記録が候補です。同じ取得処理だと確認できる記録だけを組み合わせ、別の収集の値で不足を埋めません。

**当日実測の参考値は、月末終値や月初開始時点の確定残高ではありません。** Excelの既存の確認欄に取得時刻と参考値である旨を残します。画面時計も評価基準時刻とは限りません。NISAの対象年・基準日が不明な値は、過去日の確定値へ流用しません。

**手動操作または月次タスクで実際に取得しなかった日の実測記録はありません。** 登録した月次タスクは画面のアプリを閉じていても所定のWindows条件で動く設計ですが、毎日の常時取得や、取得しなかった過去日を復元する機能はありません。記録がなければ未取得のままとし、現在額・前月比・保有株数から推計して埋めません。この節の当日最初・最後の参考記録と、新しい月次16時予定の記録も区別します。

旧版が前月比から作成した推定記録は削除しません。既存の値を保持し、資産画面とExcelの確認欄に、基準時刻・指定日残高が未確認である旨を表示します。

この環境では公式ヘルプの取得も制限され、SBIで参照できる過去日資産・NISAの範囲や、残高が確定する時刻は確認できていません。特定時刻の残高と断定せず、確認できた表示と取得日時を保存します。

## 未解析通知と停止する書類

既知の未解析書類は、確認画面と完了時に理由を表示して原本を保持します。

- **非課税口座内上場株式等払出通知書**：NISAからの払出し・口座区分移動・取得価額の変更は未反映です。売却・税額・取得単価を推定せず、原本と預り区分・取得価額の確認が必要です。
- **外国株式等株式分割・権利売却等のご案内**：分割・権利売却の金融イベントは未解析です。国内株式の株数や売却代金へ反映しません。
- 外国株式・外国債券の取引明細と債券利金通知も未解析です。年次報告書や税額0円の通知は売買・入金の追加対象外です。

**未知の書類・破損PDF・名義不一致を黙って除外しません。** それらは一括登録を停止します。ファイル名だけで対象外にする処理はありません。PDF保存と、金融イベントを解析・反映できることは別です。

## Windowsへの導入・コード更新

Python 3.10以降とTkinter、Microsoft Edgeを使います。保存設定はWindows DPAPIで暗号化しているため、元のPC・同じWindowsユーザーで利用してください。設定済みの名義・受信先・OAuthクライアントを既定値へ上書きしません。

### 導入済みフォルダを更新する

1. [GitHubリポジトリ](https://github.com/iwabuchiryousuke/API)の「Code → Download ZIP」、または `dist/family_trades_v3.5.15_code.zip` を信頼できる入手元から保存します。
2. アプリと収集処理を終了し、**現在使っているアプリフォルダの `update_windows.bat`**を実行します。
3. 新しいコードZIPを選び、更新内容を確認して適用します。
4. 依存関係の変更が表示された場合は `setup_all_windows.bat` を実行し、`start_windows.bat` から起動します。

更新前のコードは `backups/code_update_日時_識別子` へ退避します。data・口座設定・PDF・出力Excelは更新対象外です。既存の `reference/excel_layout.json` とZIPのレイアウトが異なる更新は、上書きせず中止します。チェックサムは破損の確認用で、配布元の真正性を証明するものではありません。

### 初回導入、または更新機能がない旧版からの移行

旧アプリを終了し、旧フォルダ全体を保管してください。新版を**別フォルダ**へ展開し、旧フォルダの**最新のdata全体**をコピーして、`setup_all_windows.bat` → `start_windows.bat` の順に実行します。異なる時点のdataを混在させないでください。未反映の証跡がある `data/acquisitions` も含めて移します。

既存dataは初回起動前に `backups/before_v3.5.15_日時/data` へ暗号化設定ごと退避します。退避できない場合は起動を停止します。独自調整したコード・レイアウトも含め、旧フォルダは削除しないでください。

## エラーの確認と診断ZIP

「PDF取得結果一覧」と `data/diagnostics` のログ・JSONを確認してください。「口座・認証の設定 → 診断ZIPを作成」で最新の診断を**最大20MiB**のZIPへ保存できます。自動送信はしません。

認証ファイル・台帳・PDF原本・画像は含めません。URLのセッション部分や認証情報を除去しますが、**氏名・口座情報・資産額・書類名は残る場合があります。共有前に内容を確認してください。** サイズ上限・安全性の確認で収録しなかった資料もあります。

## 検証範囲と開発

v3.5.15はGitHub `main` のv3.5.14（`a47891e`）を基準に、月次の予定・記録・Windowsタスク登録を追加しています。v3.5.14までの修正はv3.5.13とスクリーンショットを基準にしており、実際の払出通知書PDFや当時報告された最新台帳は受領していません。以前の `API-main(2).zip` は32MiBの読み込み上限を超え、内容を取得できていません。

互換性検証用の旧添付データは売買28件の台帳で、**現在の79件の台帳を検証したものではありません**。配布コードZIPにこの古いdataは含めません。ご自身の現在のアプリフォルダにある最新dataを維持してください。

生成PDF・隔離コピー・通信先を差し替えた模擬ブラウザー画面で、685テストが成功しました。**実際の該当通知書、SBI画面、Windows実機での全自動成功は未確認です。** 月次タスクも、この環境ではWindowsへ実登録していません。今回の検証は[検証結果_v3.5.15.md](検証結果_v3.5.15.md)、以前の検証は[検証結果_v3.5.14.md](検証結果_v3.5.14.md)を参照してください。

既存のチェックアウトを使い、このタスク用のGit worktreeは追加しません。テストは実データへ直接書き込まず、隔離コピーを使います。

```sh
cd /workspace/API
python3 -m venv /workspace/.venv
/workspace/.venv/bin/python -m pip install -r requirements_pdf.txt -r requirements_epost.txt -r requirements_gmail.txt
/workspace/.venv/bin/python -m unittest discover -v
```

Windowsは `run_tests_windows.bat` を使います。ブラウザー試験はEdge/Chromiumを検出し、必要なら `SBI_TEST_BROWSER` で実行ファイルを指定します。ブラウザーやNode.jsがなく実行しなかった試験は合格と区別します。試験は実際のSBI・Gmailへ接続しません。
