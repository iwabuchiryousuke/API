# SBI家族売買記録 v3.5.16

SBIのPDF・資産・NISAを取得し、内容を確認してから台帳とExcelへ反映するWindowsアプリです。既存Excelのシート・セル位置・列幅・数式・書式は維持しています。出力する値が直接確認値か当日実測の参考値かは、既存の確認欄で区別します。

## 今回の変更

- 月末・月初の標準予約に加え、**任意の日時に1回実行する無人取得**を追加できます。標準予約も時刻・PDF保存の有無を変更し、無効化・削除できます。
- Windowsでアプリを起動すると、初回は**暦月末16:00の資産取得、毎月1日16:00の資産＋PDF保存**を自動登録する処理を開始します。変更・削除した設定を次の起動で勝手に戻しません。
- 対応していない種類も、正常なPDFは原本を保管します。集計できない資料は理由付きの**保管のみ・未反映**とし、ほかの対応資料の集計を続けます。
- 保存済みPDFとSBI一覧を照合し、安全に同じ書類と確認できたものは再ダウンロードを省略します。現在値のテストではブラウザー表示とPDF取得を選べます。

**Windowsタスクの実登録・無人実行・スリープ復帰、実SBI/Gmailでの全自動成功はこの環境では未検証です。** 下記のテスト取得とWindowsへの反映状況を手元のPCで確認してください。

### v3.5.14までの主な改善

- 電子ポストへの移動で元のタブが置き換わった場合も、同じログイン状態で確認済みのSBI画面へ戻して資産を読む処理を追加しました。
- 預り金フィルター変更後に必要な「更新」と表示の反映を待つ処理、現金より遅れて表示されるNISA枠を待つ処理を見直しました。
- 「非課税口座内上場株式等払出通知書」を既知の未解析通知として識別し、原本と理由を残します。NISAからの払出し・口座区分移動は未反映で、売却・税額・取得単価を推定しません。
- 「取得した資産を確認」に、最新値・取得済み未反映、前月末・当月1日、取得日時の履歴を分けた表示を追加しました。表示だけでは台帳へ登録しません。

これらはローカルの模擬画面・生成文書・隔離データで検証する変更です。実際のSBI画面やWindows実機での成功は、まだ確認できていません。

## 自動取得の予約を設定する

### 更新後、最初に確認すること

1. アプリと収集処理を終了し、現在のフォルダの `update_windows.bat` から新版コードZIPを適用し、`start_windows.bat` で起動します。同じPC・WindowsユーザーでA～DのPDF名義・SBIログイン・Gmail連携を設定してください。
2. **「自動取得の予約・月次比較」→「取得日時の予約」**を開きます。初回起動時は標準2予約のWindows登録を自動的に開始します。予約と反映状況を確認してください。Windowsのタイムゾーンは **「(UTC+09:00) 大阪、札幌、東京」** が必要です。
3. **「今すぐテスト取得」**を実行します。初めは「テスト中のブラウザーを表示」を有効にし、SBI画面と口座別結果を確認できます。「テストでPDFも取得・保存」は必要な場合だけ有効にします。
4. Windows条件不足などで自動登録できなかった場合は、**「Windows予約を反映」**から再試行します。設定の保存とWindowsへの登録は別の状態です。失敗しても設定は残ります。

タスク結果コード0だけではSBI取得成功とは判断できません。「保存済みの実行状況」の実取得日時・不足項目・口座別の理由も確認してください。アプリ画面を閉じても、登録済みの予約は所定のWindows条件で動く設計です。

### 任意日時の追加と標準予約の変更

日時はすべて**日本時間**です。

| 操作 | 内容 |
| --- | --- |
| 日時を追加 | 将来の日付と時刻、予約名、PDF保存の有無を指定し、1回の無人取得を追加します。 |
| 選んだ予約を変更 | 標準予約の時刻・PDF設定・予約名、単発予約の日時などを変更します。 |
| 有効／無効を切替 | 設定と履歴を残し、予約の実行を止める・再開する操作です。 |
| 選んだ予約を削除 | 標準予約も含めて削除します。PDF・台帳・取得履歴は削除しません。 |
| 標準の2予約を復元 | 明示操作で標準の月末16:00・1日16:00へ戻します。追加した日時予約は残します。 |

編集画面の **「保存してWindows予約を反映」** で設定保存後にWindows登録を開始します。編集・無効化・削除は保存され、**削除した標準予約を次の起動で自動復元しません。** Windows反映が未完了なら、画面の「Windows予約を反映」から再試行してください。

初期設定は、暦月末16:00に資産、毎月1日16:00に資産とPDF保存です。標準予約の日付は暦月末・1日で、土日祝日も前営業日へずらしません。別の日に取得したい場合は日時を追加します。標準設定では `2026-10-31 16:00` と `2026-11-01 16:00` が11月の比較対象です。

予約ではA～Dのサマリー取得を先に行い、PDFありの予約はその後にPDFを取得・保存します。**自動予約で売買台帳の一括登録を確定しません。** あとで「取得済みPDFを全口座へ一括反映（A～E）」から確認・登録します。Eは保存資料のみ対象で、自動ログインしません。

互換用バッチも利用できます。`show_monthly_tasks_plan.bat` は予定表示だけ、`setup_monthly_tasks.bat` は保存した予約の反映、`monthly_tasks_status.bat` は登録確認、`test_monthly_tasks.bat` は現在資産のテストです。`remove_monthly_tasks.bat` は予約全体の解除に使い、解除した設定を次回起動で自動復元しません。フォルダ移動時は旧場所で解除し、新しい場所で登録し直してください。

### テストと失敗時の確認

「今すぐテスト取得」は現在の表示値を確認する操作です。本番の予約枠や、過去の月末・1日の取得成功として消費しません。PDFありのテストでも保存までで、台帳へ自動確定しません。ブラウザーを表示するテストで成功しても、無人取得の成功を証明したことにはなりません。

今回の通常取得ログでは、A～DのSBI/Gmailログイン・PDF保存後に「特定累積投資勘定基準額等通知書」の集計判定で一括処理が停止していました。今回の保管と集計の分離で対応する問題です。一方、月次テストの失敗画面だけでは、そのテストの直接原因は特定できません。原因を断定せず、口座別の確認理由を表示するようにしています。

追加認証・Gmail再許可・設定不足など、人による確認が必要な口座は認証待ちにし、同じ予定枠の自動再試行でログインを繰り返しません。原因を手動で確認してからテストし、**明示テストに成功した名義・口座の待ち記録だけ**を解除します。通信障害・タイムアウト等とは区別します。破損・名義変更など記録の整合性を確認できない場合は、原本を保持して停止します。

### 予定時刻と取得時刻

予定は取得を始める時刻です。A～Dを順に処理するため、全口座を予定時刻ちょうどに同時取得するものではありません。**予定日時・実取得日時・画面表示時計**を区別し、予定から30分より遅い取得は遅延として表示します。時刻を変更した予約でも、その予定と実取得時刻を残します。表示された残高が、その時刻に確定した終値・最終残高であるとは断定しません。

同じ暦日の遅延取得は実時刻を残し、翌日の取得を前日の予定へ戻して保存しません。単発予約を、取得していない過去の月末・1日の値へ読み替えません。月末・1日の比較は月次比較画面、単発予約の結果は保存済み実行状況で確認します。

月次比較のCSVは `output/monthly`、月次記録は `data/monthly`、予約ごとの証跡は `data/scheduled`、予約設定・実行状況は `data/scheduler` に保存します。比較は別出力で、既存売買Excelの形式を変更しません。差額は売買・入出金・為替等を含む表示額の増減であり、運用損益ではありません。未取得項目を0にせず、過去残高を現在額や前月比で作りません。

### PCを無人で動かす条件

標準の自動登録は**同じWindowsユーザーがログオン中**に実行する方式です。画面ロック・画面消灯中もブラウザーを表示せず処理する設計ですが、実機で確認してください。サインアウト中は標準方式では実行できません。

サインアウト中の実行が必要な場合は、予約画面でパスワード方式を選び「Windows予約を反映」を行います。求めるのは**同じWindowsユーザーのWindowsパスワード**です。PCのロック解除に使えるPIN・パスコードが、そのままWindowsアカウントのパスワードとは限りません。資格情報はWindowsの安全な入力画面で入力し、アプリのコード・設定ファイル・起動引数・ログ・GitHubへ保存しません。Windowsパスワード変更後は再登録します。S4U方式は使用しません。

スリープ解除を要求して登録しますが、実際の復帰はWindows・機器・電源設定に依存します。AC電源、スリープ解除タイマー、ふたを閉じたときの動作を確認してください。**PC電源OFF中は実行できません。** 必要なら常時稼働するWindows端末を用意し、その端末・ユーザーでSBI・Gmail設定をやり直します。DPAPIの設定をコピーするだけでは別端末で使えない場合があります。

登録時は一時PowerShellを生成し、そのプロセス以外のWindows実行ポリシーを変更しません。組織ポリシー・権限などで登録できない場合は、予約画面のWindows反映状況を確認してください。

## 取得して一括反映する

1. 必要なら「対象月末まで」に `2026-10` などの対象月を入力します。
2. **「4口座のPDF・資産・NISAを取得して一括反映」**を押します。A～DのGmail認証・SBIログイン・名義確認後、PDF、現在資産・NISA、日付を指定した資産の取得を試みます。
3. 確認画面で追加件数・未解析書類・未取得項目を確認します。「登録前Excelを確認」で内容を開けます。
4. **「登録してExcel出力」**で確定します。A～Eの保存済みPDFと取得証跡をまとめて検査し、台帳へ反映してExcelを出力します。Eは保存した資料のみ対象で、自動ログインしません。

口座選択はPDFの取得・保存先を指定します。**PDFの台帳反映は、選択口座に限らずA～Eの一括処理です。** 「選択口座のPDFだけ取得」と「手元のPDFを保存（選択口座）」は保存のみです。その後、**「取得済みPDFを全口座へ一括反映（A～E）」**で確認・登録します。この反映操作はSBIへ接続しません。

一括処理が途中で止まっても、保存済みPDFと名義を確認済みの資産取得証跡は保持します。資産画面では未反映の証跡も確認できます。証跡の破損や名義不一致は警告し、登録済み値だけを表示します。確認の取消・取得失敗を台帳登録の完了とは扱いません。

## 資産画面と通貨

「取得した資産を確認」は、次の3つに分かれます。

| 表示 | 確認する内容 |
| --- | --- |
| 最新の取得値 | 登録済みか取得済み・未反映か、画面ごとの取得日時、円評価、米ドル元額、NISA枠。以前の取得値を含む場合も表示します。 |
| 前月末・当月1日 | 表示基準日を直接確認した値、手動確認値、当日実測の参考記録、未取得の区別。 |
| 取得日時の履歴 | 取得を実行した日本時間、取得画面、画面上の表示時計、取得できた項目。 |

株式の単独の読取値と、投資信託・債券等も含む集計値を区別します。合計を構成する項目に未取得があれば、その項目を0とみなして合計しません。単独額を読み取れていても、Excelの合計欄は確認できるまで空欄になる場合があります。読み取れた株式単独額は資産画面で確認できます。

外国株式・外貨現金の**円評価**と、米ドル現金の**元通貨額**も区別します。買付余力を現金に代用せず、ドル額を円欄に入れません。スクリーンショットに外国株式や米ドルの項目が見当たらないことは、保有額0の証拠にはなりません。確認できない項目は「未取得」です。

## 前月末・月初1日の値

対象月が `2026-10` なら、取得対象日は **`2026-09-30` と `2026-10-01`** です。空欄なら日本時間の今月を使います。

優先するのは、SBI画面の基準日を直接確認した値と既存の手動確認値です。直接確認できない場合は、対象日そのものに取得した実測記録を参考として利用します。月末日はその日に最後に取得した記録、月初1日はその日に最初に取得した記録が候補です。同じ取得処理だと確認できる記録だけを組み合わせ、別の収集の値で不足を埋めません。

**当日実測の参考値は、月末終値や月初開始時点の確定残高ではありません。** Excelの既存の確認欄に取得時刻と参考値である旨を残します。画面時計も評価基準時刻とは限りません。NISAの対象年・基準日が不明な値は、過去日の確定値へ流用しません。

**手動操作または月次タスクで実際に取得しなかった日の実測記録はありません。** 登録した月次タスクは画面のアプリを閉じていても所定のWindows条件で動く設計ですが、毎日の常時取得や、取得しなかった過去日を復元する機能はありません。記録がなければ未取得のままとし、現在額・前月比・保有株数から推計して埋めません。この節の当日最初・最後の参考記録と、設定した月次予約の記録も区別します。

旧版が前月比から作成した推定記録は削除しません。既存の値を保持し、資産画面とExcelの確認欄に、基準時刻・指定日残高が未確認である旨を表示します。

この環境では公式ヘルプの取得も制限され、SBIで参照できる過去日資産・NISAの範囲や、残高が確定する時刻は確認できていません。特定時刻の残高と断定せず、確認できた表示と取得日時を保存します。

## 新規PDFの取得と、保管・集計の分離

取得前に `data/電子ポストPDF/A～D` のPDFと索引を照合します。安定した書類IDがある場合はそのID、ない場合は**全件を確認できる一意な交付日・見出しと名義**などを使います。保存済みファイルの内容ハッシュも確認し、対応関係を確認できた書類は再ダウンロードを省略します。

同じ日に同じ見出しが複数ある場合、一覧が途中までしか確認できない場合、索引がない・壊れた場合、保存済みファイルが変わった場合などは、取り漏れを防ぐため再取得します。古いPDFの初回照合は、ファイル名だけでなく本文の見出し・明示された交付日・名義等も確認します。根拠が足りなければ、その回は再取得して次回用の対応関係を作ります。

**同じ見出し・IDのままSBI側だけでPDF本文が差し替わった場合、見出し照合だけでは変更を検出できません。** 再確認が必要なときは、選択口座について「口座・認証の設定 → 保存済みPDFも再確認して取得（選択口座）」を使ってください。この明示操作だけ保存済みファイルの再利用を省略します。

SBIから取得した**構造が正常なPDFは、対応していない種類も含めて保管**します。集計時に対応資料だけを金融記録へ反映します。

- 特定累積投資勘定基準額等通知書等、売買・入金明細ではない資料は、理由を表示して集計対象外にします。
- 未知の種類、画像だけのPDF、未対応レイアウト等は原本を保持し、「保管のみ・未反映」として他の対応資料の集計を続けます。金額・株数は推定登録しません。
- NISA払出通知、外国株式等の分割・権利売却通知、外国株式・外国債券等の未解析明細も、原本と未反映理由を保持します。必要な金融イベントは確認・手動登録が必要です。
- **破損・PDF以外の内容・別名義・既存取引との不整合・確認後の原本変更**などは、正常な未対応資料と区別して停止します。既存値を上書きしません。

PDFの保管、金融イベントの解析、台帳登録はそれぞれ別の状態です。取得結果と一括確認で、新規・保存済み照合・保管のみの件数や理由を確認してください。

## Windowsへの導入・コード更新

Python 3.10以降とTkinter、Microsoft Edgeを使います。保存設定はWindows DPAPIで暗号化しているため、元のPC・同じWindowsユーザーで利用してください。設定済みの名義・受信先・OAuthクライアントを既定値へ上書きしません。

### 導入済みフォルダを更新する

1. [GitHubリポジトリ](https://github.com/iwabuchiryousuke/API)の「Code → Download ZIP」、または `dist/family_trades_v3.5.16_code.zip` を信頼できる入手元から保存します。
2. アプリと収集処理を終了し、**現在使っているアプリフォルダの `update_windows.bat`**を実行します。
3. 新しいコードZIPを選び、更新内容を確認して適用します。
4. 依存関係の変更が表示された場合は `setup_all_windows.bat` を実行し、`start_windows.bat` から起動します。

更新前のコードは `backups/code_update_日時_識別子` へ退避します。data・口座設定・PDF・出力Excelは更新対象外です。既存の `reference/excel_layout.json` とZIPのレイアウトが異なる更新は、上書きせず中止します。チェックサムは破損の確認用で、配布元の真正性を証明するものではありません。

### 初回導入、または更新機能がない旧版からの移行

旧アプリを終了し、旧フォルダ全体を保管してください。新版を**別フォルダ**へ展開し、旧フォルダの**最新のdata全体**をコピーして、`setup_all_windows.bat` → `start_windows.bat` の順に実行します。異なる時点のdataを混在させないでください。未反映の証跡がある `data/acquisitions` も含めて移します。

GUIを開かず予約から新版を初回実行する場合も、認証更新やDB操作より前にdata全体を退避します。既存dataは初回起動前に `backups/before_v3.5.16_日時/data` へ暗号化設定ごと退避します。退避できない場合は起動を停止します。独自調整したコード・レイアウトも含め、旧フォルダは削除しないでください。

## エラーの確認と診断ZIP

「PDF取得結果一覧」と `data/diagnostics` のログ・JSONを確認してください。「口座・認証の設定 → 診断ZIPを作成」で最新の診断を**最大20MiB**のZIPへ保存できます。自動送信はしません。
