v3.5.9 名義表示待ちの修正（実サイト確認前）

今回のログで確定したこと
Gmail認証後、電子ポストへ移動し、名義確認で停止しています。
PDF保存・解析の段階には進んでいません。

確認した実装上の問題
旧処理は電子ポストのURLが開いた直後、本文を一度だけ読みました。
氏名未表示でも別名義と同じエラーにしていました。
この状態をテストで再現し、修正後は表示を待つことを確認しました。
ただし実際の今回の停止原因が読み込み遅延だったかは、旧ログだけでは断定できません。

修正
・最大30秒、名義表示を待つ。
・空表示・一時的な本文取得失敗・同じ電子ポストのフレーム内表示に対応。
・空白、改行、ゼロ幅文字を正規化して照合。
・別の家族名義や複数名義を検出した場合は停止。照合を省略しない。
・未確認を別名義と断定しない。
・診断ログにMATCH/MISMATCH/NOT_RENDERED、文字数、読取回数を記録。
・停止時の電子ポスト画面を data/diagnostics/post_failure_*.png に保存。
  この画像には口座情報が含まれる可能性があります。共有前に確認してください。

変更していない部分
PDF収集(epost_collector.py)、PDF解析(pdf_import.py)、一括取込(pdf_batch.py)、台帳(ledger.py)
はv3.5.7とファイル単位で同一です。

検証範囲
169件のローカルテスト成功。
内9件は今回追加：遅延表示、誤口座、空白・ゼロ幅、タイムアウト、同一ホストフレーム、
他ホスト拒否、読取例外後回復、複数名義拒否、停止画像の保存対象制限。
Windows Edge・実際のSBI電子ポストでの動作成功は未確認です。
ローカルブラウザでの追加検証を試みましたが、ブラウザ配布ファイルの取得に失敗しました。
これは完成保証版ではなく、確認できた問題を修正し、残る原因を判別できるようにした版です。

移行
1. 旧アプリを閉じ、旧フォルダ全体をバックアップ。
2. ZIPを展開し、旧版のdataフォルダを新フォルダへコピー。
3. v3.5.7のセットアップ済みなら再セットアップ不要。start_windows.batで起動。
4. 同じA口座で確認。停止時は最新auto_*.txtとpost_failure_*.pngを確認。
既存PDFを捨てたり再取得し直す必要はありません。
