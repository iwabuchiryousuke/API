# SBI家族売買記録 v3.6.0

画面とExcelを、今回の「取引シート見本.xlsx」とご指定の運用に合わせて作り直しました。普段は **「4口座のPDF・円・米ドル・NISAをまとめて取得」** から取得し、内容を確認してExcelへ反映します。

前月末・当月1日の現金を過去へ遡って復元する運用と、定期・指定日時の無人取得は終了します。現金とNISA枠は、実際に取得できた時点の値を記録します。既存の取引・PDF原本・口座設定・過去の取得履歴は保持します。

## 更新と初回確認

1. アプリと取得処理を終了し、現在使っているフォルダの `update_windows.bat` から、信頼できる入手元の `family_trades_v3.6.0_code.zip` を適用します。
2. `start_windows.bat` で起動します。既存dataは初回起動前に `backups/before_v3.6.0_日時/data` へ退避します。退避できない場合は起動・取得を停止します。
3. 「設定・補助」で必要な口座名・PDF名義・SBIログイン・Gmail連携を確認します。設定時だけ対象口座を選び、通常の取得画面では口座を選びません。
4. 4口座まとめ取得を実行し、確認画面の追加件数・保管のみの資料・未取得項目を確認します。「登録前Excelを確認」で出力内容を開き、「登録してExcel出力」で確定します。

新規導入・更新機能がない旧版からは、新版を別フォルダへ展開して、現在使っている最新の `data` 全体をコピーし、`setup_all_windows.bat` → `start_windows.bat` の順に実行します。異なる時点のdataや、配布用の古い見本dataを混ぜないでください。暗号化された連携設定は、元と同じPC・Windowsユーザーで使用します。

今回から新しいExcel配置を使います。**既に保存したExcelを変更するものではありません。** 新しいファイルは `output` に作成します。旧レイアウト用の `reference/excel_layout.json` は互換性確認用に保持し、新しい配置はPythonモジュール側で作成するため、v3.5.16の更新機能からも更新できます。

## 画面の操作

| 操作 | 内容 |
| --- | --- |
| 4口座のPDF・円・米ドル・NISAをまとめて取得 | A～Dを順に認証し、PDFと取得時点の円現金・米ドル現金・NISA2枠を取得します。確認後に台帳とExcelへ反映します。 |
| 父のPDF取り込み | 取り込み先を父口座Eに固定して、手元のPDFを保存・確認します。父のPDF名義は設定で確認してください。Eへ自動ログインしません。 |
| 税還・利息を手動で追加 | 口座・日付・税還または利息・金額の4項目で登録します。配当の手入力はありません。 |
| Excelを出力 | 登録済みの内容から「取引」「配当」を出力します。出力対象月は `YYYY-MM`、空欄は全期間です。 |

口座選択、口座ごとの取得、PDF保存フォルダ・取得結果一覧、手動分割登録、取得資産の別画面、予約・月次比較は通常画面から外しました。保存済み資料からの再確認が必要な場合は「設定・補助 → 保存済みPDFから再作成」を使います。

「税還・利息を手動で追加」の行は配当シートに入り、日付・口座・分類・金額を記載します。銘柄・コード・預り・数量・単価は空欄です。同じ口座・日付・区分・金額の記録を重ねて登録しません。PDFに既に入っている同じ入金を手動で追加する前に、登録内容を確認してください。

## 取引シート

添付見本と同じく、A～Jが取引、K～Mが計算、O～Sが取得時点の口座情報です。

| 列 | 内容 |
| --- | --- |
| A～J | 日付、口座、銘柄、コード、預り、B/S、数量、単価、受渡金額、手数料・税額 |
| K | その行の取引後の保有株数をExcel数式で計算 |
| L | 平均取得単価をExcel数式で計算。日次の合算後に切り上げ |
| M | 売却時の確定損益をExcel数式で計算 |
| O1 | 実際の取得記録の日付。未取得なら空欄 |
| O2以降 | 口座名。P～Sは同じ行の口座の値 |
| P・Q | NISA成長枠残高・つみたて枠残高 |
| R・S | 円現金・米ドル現金の元通貨額 |

### 同日取引の合算

約定日・口座・銘柄コード・預り区分・売買区分がすべて同じ取引を、計算前に1行へまとめます。数量G・受渡金額Iをそれぞれ合計し、株式の単価Hは合計受渡金額÷合計数量で算出します。投資信託は価格単位を維持し、1万口単位の単価は1万口当たりで表示します。コードがない投信は名称も区別し、別の投信を混ぜません。

原本PDF・DBの明細・証跡は合算して削除・置換せず、元のまま保持します。画面と新しいExcelの計算用入力を合算するため、既存の明細と新たに取り込んだ明細の両方に適用できます。

同日内の計算順は **分割 → 買い → 売り** です。分割の追加株数は、現金0円の別のB行として残し、実際の買付と合算しません。数量は増やし、原価総額を新たに追加しません。既存の分割記録と対応するPDFからの分割情報は保持します。

買付履歴・開始残高・分割前の数量等が不足し、原価を確認できない行では、平均取得単価や売却益を0から作りません。未確認の計算結果は空欄です。受渡金額を基準とした日次計算であり、SBIの税務上の取得価額とすべての条件で一致したことを確認したものではありません。

### 取得時点の現金とNISA

今回の4口座の取得処理を、まとまりとして保存します。口座ごと・画面ごとの実取得時刻を保持し、別の取得の値で空欄を埋めません。米ドルの元額と円評価、買付余力と現金残高を区別します。NISA枠は表示の対象年も確認します。

A～Dは順に取得するため同時刻ではありません。未取得項目・父口座Eの自動取得欄は空欄です。現金が0と明示されていれば0を記録し、読めなかったことを0とは扱いません。出力対象月を変えても、O1は実際の取得日で、過去月の残高へ読み替えません。取得自体を行わずExcelだけを作る場合は、最後に確認して登録した取得記録を使い、記録がなければ空欄です。

## 配当シート

明細はA～Iに詰め、手数料・税額の列を外しました。配当金はPDFの実入金額を使います。右側はJを区切りとして、銘柄別のまとめをK～Yへ連続して配置します。株価日・出典確認日の独立列と、旧M24・M25の説明は表示しません。

- 銘柄別のまとめには、権利付き最終日、配当金支払日、本決算発表日、株数、DPS、利回り、実績・予想・累計等を表示します。
- 前月末日終値と今月1日終値をX・Yへ横並びに表示します。前月末は最終営業日の終値を確認し、当月1日はその日付の終値だけを使います。1日が休場日、終値未確定、取得できない場合は空欄とし、別の日の株価を代用しません。
- 銘柄別まとめの終了から2行を空け、配当・税還・利息の年別集計と累計を置きます。累計はExcelのSUM式、次の「総計」の右側はその3種類の累計のSUMです。
- 累計ブロックの終了から2行を空け、K列に「カレンダー」と記載します。その下はK日付・L銘柄・M分類・N配当金額で、日付の古い順です。列名だけの見出し行は追加しません。
- カレンダーの分類は権利付き最終日・配当金支払日・本決算発表日です。支払日は確認できた実績または予想金額を表示し、数値の書式で「実績」「予想」を区別します。金額を確認できない予定は空欄です。
- 今日以降で最も近い出来事を1件だけ薄赤にします。ExcelのTODAY式による条件付き書式なので、開いた日付に応じて対象が変わります。

取得時は、PDFの後に銘柄コードと出力対象月から公開終値の更新も試みます。取得待ちには上限を設け、通信失敗・休場・対象日を確認できない価格は空欄です。既存の確認済み情報や手動入力した参照データは保持します。

配当予定・株価の出典と確認日は内部の参照データに残します。「設定・補助 → 配当予定・終値を確認」で、予定・終値・実際の株価日・出典を確認・修正できます。予想配当と実際の入金は区別し、予定や価格の不足から金融記録を推測しません。

## PDFの保存・集計・再取得

有効なPDFは、対応していない種類も原本を保管します。売買明細でない通知、画像のみ・未解析レイアウト等は、理由付きの「保管のみ・未反映」として、その資料だけを集計から外し、他の対応資料を続けます。未解析の外国株式等の金融イベントを解析済みにしたものではありません。

保存済みPDFは、名義・書類IDまたは見出し・日付・原本ハッシュ等で照合し、同じ書類と確認できるものは再ダウンロードを省略します。初回に根拠が足りない場合、同日同名、絞り込み条件や一覧全体が不確かな場合は再取得します。見出しが同じままSBI側だけで本文が差し替わる場合は、通常の見出し照合だけでは検出できません。

破損・PDF以外の内容・読み取れた名義の不一致・既存台帳との競合・確認後の原本変更は停止し、既存の金融記録を上書きしません。取得済み資料は、確認を中止しても保持します。保存済み資料からの再作成は「設定・補助」から行います。

## 旧予約の終了

この版では月末・月初・指定日時の無人取得を行いません。アプリ起動時は、旧予約の停止記録を先に保存して予約設定を削除扱いにし、このアプリ所有のWindowsタスクの停止・解除を試みます。検証できた同一ユーザーの旧フォルダ情報がある場合は、その旧フォルダのタスクも対象にします。旧フォルダのファイルは変更せず、台帳・PDF・口座設定・過去の取得履歴を削除しません。

旧タスクが新版の起動先を呼んでも、取得処理へ進みません。停止を確認できない案内が画面に出た場合、旧フォルダのタスクスケジューラ登録も確認してください。再試行するには、このアプリフォルダで `py -3 windows_tasks.py --action retire` を実行します。古いフォルダの旧プログラムが残っている場合、Windows側の解除に失敗したまま停止済みとは判断しません。

旧版の予約作成・変更用バッチは使いません。今後の取得はアプリの4口座まとめ取得から実行してください。PCを起動していない間に、自動で新しい取得値を作る運用は行いません。

## 検証範囲と開発

基準はGitHub `main` のv3.5.16（`0b80c8d`）です。変更前の全Git履歴bundle・ソースZIP・manifestを `/workspace/backups/before_v3.6.0/` へ保存しました。添付Excelは配置・数式の見本として確認し、その実データや外部ブック参照を配布コードへ取り込んでいません。

新しい配置の単体・結合試験に加え、合成データのExcelをLibreOfficeで実際に再計算する検証を行っています。Windows版Excelそのものや、実SBI・Gmailへの接続を検証した結果ではありません。実ブラウザー試験の通信はテスト応答に差し替えます。最終件数・配布ハッシュ・確認した範囲は[検証結果_v3.6.0.md](検証結果_v3.6.0.md)と `dist/verification_summary.json` を参照してください。

以前の添付dataの台帳は28取引の互換性確認用で、手元の現在の79件のDBを検証したものではありません。今回の見本Excelも現在のDBの代わりにはしません。配布コードZIPに古いdata、添付Excel、PDF原本、認証設定を含めません。現在使っている最新dataを維持してください。

```sh
cd /workspace/API
python3 -m venv /workspace/.venv
/workspace/.venv/bin/python -m pip install -r requirements_pdf.txt -r requirements_epost.txt -r requirements_gmail.txt
/workspace/.venv/bin/python -m unittest discover -v
```

Windowsの開発用試験は `run_tests_windows.bat` です。ブラウザー試験はEdge/Chromiumを検出し、必要なら `SBI_TEST_BROWSER` を指定できます。Office再計算試験はLibreOfficeを検出し、必要なら `SBI_TEST_OFFICE` を指定します。開発用のOffice検証はアプリの実行時依存関係ではありません。実行できなかった試験は合格と区別します。
