# SBI家族売買記録 v3.5.13

SBIのPDF・資産・NISAを取得し、内容を確認してから取引台帳とExcelへ反映するWindowsアプリです。既存Excelのシート構成・セル位置・列幅・書式・数式は維持しています。

## 通常の使い方

1. 必要なら「対象月末まで」に `2026-10` などの対象月を入力します。
2. **「4口座のPDF・資産・NISAを取得して一括反映」**を押します。A～DのGmail認証・SBIログイン・名義確認後、電子ポストのPDF、現在の資産・NISA、指定日の資産を順に取得します。
3. 登録前の画面で、追加件数・未解析書類・未取得項目を確認します。「登録前Excelを確認」で内容を開けます。
4. **「登録してExcel出力」**で確定します。A～Eの保存済みPDFと取得証跡をまとめて検査し、台帳へ反映してExcelを出力します。Eは保存した資料のみ対象で、自動ログインしません。

取得先の口座選択は、PDFを取得・保存する先を指定します。**台帳へのPDF反映は選択口座に限らずA～Eの一括処理です。** 次の操作は保存だけで、売買記録を変更しません。

- 「選択口座のPDFだけ取得」：その口座のPDFを自動保存。
- 「手元のPDFを保存（選択口座）」：手元のPDFをその口座の保存フォルダへ追加。

その後、**「取得済みPDFを全口座へ一括反映（A～E）」**でまとめて確認・登録できます。この操作はSBIへ接続しません。途中で別口座の取得に失敗した場合も、保存済みPDFと名義を確認済みの資産取得証跡を次回に利用します。確認の取消・取得失敗を、台帳登録の完了とは扱いません。

## 資産・NISAの日付と通貨

取得対象は、国内株式等の円評価、外国株式の円評価、円の現金合計、外貨現金の円評価、米ドル現金の元通貨額、NISA成長・つみたて枠です。「取得した資産を確認」で元通貨額や取得日時を確認できます。買付余力を現金に代用せず、ドル額を円欄に入れません。

指定日の取得対象は**対象月の前月末と月初1日**です。たとえば `2026-10` では `2026-09-30` と `2026-10-01`、対象月が空欄なら取得時の日本時間の月を基準にします。画面上の日付と項目を確認できた実額だけを採用し、日付指定画面への移動も試みます。NISAを含め過去日の表示がない項目は未取得と表示し、現在値・前月比からの推計値で埋めません。

同日の手動記録は保持します。別口座の名義、指定日との不一致、確認済み値との矛盾がある場合は停止または未取得として表示します。「全項目を取得できた」と表示できる条件と、一部を保存できた状態は区別しています。

## 未解析PDFの扱い

「外国株式等株式分割・権利売却等のご案内」は、今回、書類本文のタイトルから識別する対象に追加しました。**金融イベントの解析には未対応です。** 確認画面と完了時に未解析の警告を表示し、原本を保持します。国内株式の株数や売却代金へ推測で反映しません。

外国株式・外国債券の取引明細と債券利金通知も未解析です。年次報告書や税額0円の通知は取引追加の対象外です。識別できた対象外書類は理由を表示して他の資料の処理を続けますが、**未知の書類・破損PDF・名義不一致を黙って除外しません。** それらは一括登録を停止します。PDF保存と、取引として解析・登録できることは別です。

## Windowsへの導入・更新

Python 3.10以降とTkinter、Microsoft Edgeを使用します。SBI・Gmailの保存設定はWindows DPAPIで暗号化しているため、既存設定は元のPC・同じWindowsユーザーで利用してください。設定済みの名義・Gmail受信先・OAuthクライアントを既定値へ上書きしません。

### 初回導入、または更新機能がない旧版からの移行

1. 旧アプリと収集処理を終了し、旧フォルダ全体を保管します。
2. 信頼できるGitHubのコードZIPを**別フォルダ**へ展開します。GitHubには取引台帳・PDF・認証設定を含めていません。
3. 旧フォルダの**最新の `data` フォルダ全体**を新版へコピーします。古い同梱データや他版のファイルと継ぎ足して混在させないでください。
4. `setup_all_windows.bat`、`start_windows.bat` の順に実行します。

既存dataは新版の初回起動前に `backups/before_v3.5.13_日時/data` へ暗号化設定ごとバックアップします。退避を確認できない場合は起動を停止します。独自に出力形式を調整した場合も、元のコードとレイアウトを含む旧フォルダを残してください。

### コードだけを更新する

更新機能を導入済みのフォルダでは、次の手順でdataを移し直さずにコードを更新できます。`update_windows.bat` がない旧版は、まず上の別フォルダへの移行を使ってください。

1. [GitHubリポジトリ](https://github.com/iwabuchiryousuke/API)の「Code → Download ZIP」、または `dist/family_trades_v3.5.13_code.zip` を信頼できる入手元から保存します。
2. アプリと収集処理を終了し、**現在使っているアプリフォルダの `update_windows.bat`**を実行します。
3. 保存したコードZIPを選び、更新内容を確認して適用します。
4. 依存関係の変更が表示された場合は `setup_all_windows.bat` を実行し、`start_windows.bat` から起動します。

更新前のコードは `backups/code_update_日時_識別子` へ退避します。ZIP中のdata・認証設定・PDF・出力Excelは更新対象外です。既存の `reference/excel_layout.json` とZIPのレイアウトが異なる場合は、上書きせず更新を中止します。チェックサムは破損の確認用で、配布元が正しいことの証明にはならないため、不明な入手元のZIPは使用しないでください。

## エラーの確認と診断ZIP

「PDF取得結果一覧」と `data/diagnostics` の `auto_*.txt`・`navigation_*.json` を確認してください。「口座・認証の設定 → 診断ZIPを作成」で、最新のログ・資産JSON・ジョブ状態・PDF取得結果を**最大20MiB**のZIPに保存できます。自動送信はしません。

診断ZIPには認証ファイル・取引台帳・PDF原本・画像を含めません。URLのセッション部分や認証情報を除去しますが、**氏名・口座情報・資産額・書類名は残る場合があります。共有前に内容を確認してください。** アプリ全体やdata全体を送る必要はありません。サイズ上限・安全性の確認で収録しなかった資料もあります。

## 検証範囲と開発

今回の実装基準はGitHub `main` のv3.5.12（`e1b5d77`）です。新しい添付 `API-main(2).zip` はこの環境の32MiBの読み込み上限を超え、内容を取得できていません。該当の外国株式分割通知PDFも未取得です。報告されたエラーとコードを基に修正し、模擬文書・隔離データ・模擬ブラウザー画面で確認しています。**実際の該当PDF・SBI画面・Windows実機での成功は未確認です。** 日付指定・外貨画面は、実画面でも同じ表示を確認できた場合だけ採用します。

実施した試験と残る制限は[検証結果_v3.5.13.md](検証結果_v3.5.13.md)を参照してください。以前の検証は[検証結果_v3.5.12.md](検証結果_v3.5.12.md)にあります。

既存のチェックアウトを使い、このクラウドタスク用のGit worktreeは追加しません。テストは実データへ直接書き込まず、隔離コピーを使います。

```sh
cd /workspace/API
python3 -m venv /workspace/.venv
/workspace/.venv/bin/python -m pip install -r requirements_pdf.txt -r requirements_epost.txt -r requirements_gmail.txt
/workspace/.venv/bin/python -m unittest discover -v
```

Windowsは `run_tests_windows.bat` を使います。ブラウザー試験はEdge/Chromiumを検出し、必要なら `SBI_TEST_BROWSER` に実行ファイルを指定します。ブラウザーやNode.jsがない試験のスキップは、合格とは区別してください。試験は実際のSBI・Gmailへ接続しません。
