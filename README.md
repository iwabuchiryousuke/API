# SBI家族売買記録 v3.6.3

1枚の配当PDFに複数銘柄が載る場合、先頭だけを登録してPDF全体を処理済みにする不具合を修正しました。旧版で取り込み済みのPDFも検証し直し、既存の配当を保持したまま不足分を復元します。

1. アプリを終了し、`update_windows.bat`で`dist/family_trades_v3.6.3_code.zip`を適用。
2. `start_windows.bat`で起動し、`保存PDFを反映`を実行。
3. 追加される配当を確認して、`登録してExcel出力`を実行。

PDFを再ダウンロードしたり、既存データを削除したりする必要はありません。再実行しても同じ配当を重複登録しません。既に出力した古いExcelは保持し、新しいExcelを作成します。

全明細の算術・名義・既存記録との整合性を確認し、一括保存します。後ろの行が不明な通知を先頭だけ登録しません。全明細とPDFの対応を証明する記録を、金融明細と同じトランザクションで保存します。旧版の1件だけのPDF対応記録は完了の証拠として扱いません。

既存イベントのID・本文・PDF原本を保持し、スキーマの追加も確定時だけ行います。確認を中止した場合は台帳に追加しません。画面・Excelの書式・集計式・月初終値の扱いはv3.6.2の構成を維持します。

操作は[はじめに_v3.6.3.txt](はじめに_v3.6.3.txt)、検証範囲は[検証結果_v3.6.3.md](検証結果_v3.6.3.md)と`dist/verification_summary.json`を参照してください。コードZIPに個人data・添付PDF・出力Excel・認証設定を含めません。現在の最新dataを維持して更新してください。

添付の実PDFを使った復元・重複防止・Excel再計算を確認します。実SBI・Gmailへの接続、Windows実機・Windows版Excelは未検証です。開発時は`python -m unittest discover -v`、Windowsは`run_tests_windows.bat`を使用します。新しい実行時依存関係はありません。
